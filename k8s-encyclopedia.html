15 Essential Kubernetes & EKS Terms to Remember First

If you are just starting out in DevOps, memorize these 15 foundational building blocks first. Almost every Kubernetes YAML file and AWS architecture diagram is made of these pieces.

No. Term Remember It As Plain-English Definition
01 Cluster The complete Kubernetes environment A group of machines (Control Plane + Worker Nodes) working together as one system to run containers.
02 Node A machine in the cluster A physical or virtual server (like an AWS EC2 instance) that provides CPU and RAM to run Pods.
03 Pod The smallest deployable unit A thin wrapper around one or more containers that shares a single IP address and storage volume.
04 Container The application runtime box Your packaged app and its libraries running inside a Pod (powered by containerd or Docker).
05 Deployment Manages application Pods The resource you write to declare how many copies of your Pod should run and how to update them safely.
06 ReplicaSet Maintains desired Pod count The background watchdog managed by a Deployment that immediately starts a new Pod if one crashes.
07 Service Stable network access to Pods A permanent IP address and DNS name in front of short-lived Pods so traffic always finds healthy copies.
08 Namespace Organizes cluster resources A virtual sub-cluster (like folders for dev, staging, and prod) inside one physical cluster.
09 ConfigMap Stores non-sensitive settings Holds plain-text configuration (like URLs, feature flags, or ports) decoupled from your container image.
10 Secret Stores sensitive credentials Holds passwords, API keys, and TLS certificates separately from code so they are never hardcoded.
11 kubectl Communicates with Kubernetes The command-line remote control used to inspect, deploy, scale, and debug cluster resources.
12 YAML Defines resource configuration The human-readable text format used to write Kubernetes manifest files declaring your desired state.
13 Ingress HTTP/HTTPS routing rules The smart front-door router that directs domain names and URL paths (like /api) to internal Services.
14 HPA Auto-adjusts Pod replicas Horizontal Pod Autoscaler—adds more Pods when CPU/memory spikes and scales down when traffic drops.
15 Amazon EKS AWS's managed Kubernetes service Runs and patches the Kubernetes Control Plane for you across multiple AWS Availability Zones.

Phase 4 & Phase 9 · CLI Reference

Important kubectl & Troubleshooting Commands

These are the daily terminal commands you will use to inspect nodes, deploy YAML manifests, read logs, and debug failing Pods.

Command Simple Definition
kubectl get pods Lists Pods in the current namespace along with their status and restart count.
kubectl get pods -o wide Lists Pods with extra details including their internal IP address and assigned Worker Node.
kubectl get nodes Lists all Worker Nodes in the cluster and shows whether they are Ready.
kubectl get deployments Lists Deployments in the current namespace and shows how many replicas are ready.
kubectl get services Lists Services and their internal ClusterIP, NodePort, or external LoadBalancer URL.
kubectl apply -f file.yaml Creates or updates Kubernetes resources based on a YAML manifest file.
kubectl delete -f file.yaml Deletes the Kubernetes resources defined in that YAML manifest file.
kubectl describe pod <pod-name> Displays detailed configuration and recent cluster Events for a Pod (essential for debugging Pending or ImagePullBackOff).
kubectl logs <pod-name> Prints the stdout/stderr logs from a container inside a Pod (add --previous if the container crashed).
kubectl exec -it <pod-name> -- sh Opens an interactive shell inside a running container so you can inspect files or test network connectivity.
kubectl get events --sort-by=.metadata.creationTimestamp Shows a chronological timeline of cluster events (scheduling, image pulls, probe failures).
kubectl rollout status deployment/<name> Watches a rolling update in real time until all new Pods are healthy.
kubectl rollout history deployment/<name> Lists past revisions of a Deployment so you can audit or roll back changes.
kubectl rollout undo deployment/<name> Immediately rolls a Deployment back to its previous working version.
