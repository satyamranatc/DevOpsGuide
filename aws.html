AWS essentials,

01

What AWS actually is

Say you want to put a website online. The old way: buy a computer, plug it in, keep it running day and night, and hope it never breaks. If your site suddenly gets popular, you’d need to buy more computers and wait for them to arrive.

AWS (Amazon Web Services) is the other way. Amazon owns enormous buildings full of computers, and it rents them out by the hour. You ask for what you need, it’s ready in minutes, and you hand it back when you’re done.

You only pay for what you use, like electricity. Nothing to buy, nothing to store.

In one line

AWS lets you rent computers, storage and networks over the internet, and pay only for what you use.

02

Regions and zones

AWS’s buildings are spread across the world. Two words describe where they are.

Region

A part of the world, like Mumbai, Frankfurt or Virginia. You pick one close to your users, so your site feels fast.

Availability Zone

A separate building (or group of them) inside a region, with its own power and network. Often called an AZ.

Why do zones matter? Buildings have bad days: a power cut, a fire, a flood. If your app lives in two zones at once, one going down doesn’t take you offline.

Think of it as

A region is a city. Zones are separate neighbourhoods in that city. If one neighbourhood loses power, the others carry on.

03

The city idea

AWS has over two hundred services, which sounds scary. Don’t worry. Nearly every beginner project uses the same few. Picture them as parts of a city.

IAM

The security office. Decides who gets a key, and which doors that key opens.

EC2

Rented computers. The workers who actually run your app.

S3

A giant warehouse for files: photos, videos, backups, anything.

VPC

Your own fenced-off land inside the city, with your own roads and gates.

RDS

A managed filing room for your data (a database), cared for by AWS.

Load balancer

The receptionist. Greets every visitor and sends each to a free worker.

Auto Scaling

The hiring manager. Adds workers when it’s busy, sends them home when it’s quiet.

CloudWatch

The CCTV and alarm system. Watches everything and warns you when something’s wrong.

04

IAM: who can do what

Before you create anything, learn IAM (Identity and Access Management). It controls who can enter your AWS account and what they’re allowed to do.

When you sign up, you get a root user. It’s the master key. It can do everything, including deleting your whole account.

The golden rule

Lock the master key away. Use it once to set up, then give yourself a normal key for everyday work.

The four IAM words

User

One person (or program) with their own login.

Group

A team of users who share the same permissions, like “developers”.

Policy

A short rulebook: “allowed to read files in this bucket, nothing more.”

Role

A temporary hat. A server or service puts it on to get permissions, with no passwords involved.

Do these three things on day one

  • Turn on MFA for the root user. That’s the code from an app on your phone, on top of your password.
  • Create your own IAM user and use that for daily work, never the root user.
  • Give the smallest permissions that work. This is called least privilege. Start with little and add more when you need it.
05

EC2: your servers

EC2 (Elastic Compute Cloud) gives you a computer in the cloud. AWS calls each one an instance. It’s a real server where you can install and run anything.

When you launch one, you choose a few things:

  • An image (AMI). The starting software, such as Ubuntu or Amazon Linux.
  • A size. How much power. A t3.micro is small and cheap. Bigger names mean more power and a bigger price.
  • A key pair. A secret file that lets you log in. Keep it safe, because you can’t download it twice.
  • A security group. A list of which doors are open, such as port 22 for logging in or port 80 for a website.

Instances are billed while they’re running. Stop one and you stop paying for the computer. Terminate it and it’s gone for good. Read the full EC2 guide →

06

S3: your storage

S3 (Simple Storage Service) stores files. Any number of them, any size, and AWS keeps copies so they’re very hard to lose.

Files go into a bucket, which is like a top-level folder. Each file inside is called an object.

Great for

Images and videos for your app, backups, log files, and even simple static websites.

Remember

Bucket names must be unique across all of AWS, and buckets are private by default. Keep them that way unless you truly need otherwise.

S3 is also very cheap, and you pay only for what you store. That’s why almost every AWS project ends up using it.

07

VPC: your private network

A VPC (Virtual Private Cloud) is your own private section of AWS. Your servers and databases live inside it, cut off from everyone else’s.

Inside a VPC you split things into two kinds of areas, called subnets:

Public subnet

Can talk to the internet. Put things here that visitors need to reach, like a load balancer.

Private subnet

Hidden from the internet. Put your databases here. Only your own servers can reach them.

Think of it as

A shop with a front room and a back room. Customers come into the front. The safe is kept in the back, where only staff can go.

08

Databases, load balancers, scaling

Three more services turn “one server” into a proper, dependable app.

RDS · a database AWS looks after

Apps need to remember things: users, orders, messages. That’s a database. RDS (Relational Database Service) runs one for you. AWS handles the backups, updates and fixing. You can ask it to keep a spare copy in a second zone, so a failure doesn’t lose anything.

Load balancer · one front door

When you have several servers, visitors need a single address to use. The load balancer gives you that. It spreads visitors across your servers, and it stops sending anyone to a server that has crashed.

Auto Scaling · the right number of servers

Traffic isn’t steady. Auto Scaling watches how busy you are. Busy evening? It adds servers. Quiet night? It removes them, so you stop paying for idle ones. It also replaces any server that dies.

Put together

Load balancer in front, a few servers behind it in two zones, a database in the back, and Auto Scaling keeping the count right.

09

The whole picture

A typical small app on AWS. Visitors arrive at the load balancer, which shares them across two servers in different zones. Both read from the database, and files live in S3.

10

Costs and staying safe

AWS is pay-as-you-go, which is great, until you forget to turn something off. Most horror stories come from a forgotten server running for a month. A few habits prevent that.

  1. Set a budget alert first

    Before creating anything, open Billing → Budgets and make a small budget, for example $5. AWS will email you if you’re about to go over it.

  2. Use the Free Tier

    New accounts get a limited amount of free usage, such as small servers, storage and databases. Check the current limits on the AWS Free Tier page, because they change.

  3. Pick one region and stay in it

    Resources you forgot in another region still cost money, and they’re easy to miss. Look at the region name in the top-right corner of the console.

  4. Clean up when you’re done

    Terminate practice servers, delete test databases and empty buckets. If you don’t need it, delete it.

Watch out

Never put your access keys in code or on GitHub. Bots scan for them within minutes and can run up a huge bill on your account.

11

Try it: the AWS CLI

You can do everything with clicks in the console, but the AWS CLI lets you type commands instead, which is faster and can be saved in scripts. Install it from the AWS website, then connect it to your account.

Step 1 · Connect

Create an access key for your IAM user (not root), then run this and paste the values when asked.

# one-time setup
aws configure
# asks for: Access Key ID, Secret Access Key,
#          region (e.g. ap-south-1), output format (json)

# check who you're logged in as
aws sts get-caller-identity

Step 2 · Use S3

Make a bucket, upload a file and look inside it. Bucket names must be unique everywhere, so add something personal to yours.

# make a bucket
aws s3 mb s3://my-first-bucket-12345

# upload a file
aws s3 cp hello.txt s3://my-first-bucket-12345/

# list what's inside
aws s3 ls s3://my-first-bucket-12345/

# download it again
aws s3 cp s3://my-first-bucket-12345/hello.txt copy.txt

# clean up: delete the bucket and everything in it
aws s3 rb s3://my-first-bucket-12345 --force

Step 3 · Look at your servers

# list your EC2 servers and their state
aws ec2 describe-instances \
  --query "Reservations[].Instances[].[InstanceId,State.Name]" \
  --output table

# stop a server (replace with your own ID)
aws ec2 stop-instances --instance-ids i-0123456789abcdef0

# start it again
aws ec2 start-instances --instance-ids i-0123456789abcdef0

A few more worth knowing

aws iam list-users

See who has a login in your account.

aws s3 ls

List all your buckets.

aws ec2 describe-regions

List the regions you can use.

aws <service> help

Show help for any service, for example aws s3 help.

12

Quick recap

  • AWS rents you computers, storage and networks, and you pay for what you use.
  • A region is a place in the world. Zones are separate buildings inside it.
  • IAM controls access. Protect the root user, use MFA, give the least permissions.
  • EC2 gives you servers. S3 stores files.
  • A VPC is your private network, with public and private areas.
  • RDS, a load balancer and Auto Scaling make an app dependable.
  • Set a budget alert first, and delete what you don’t use.
If you remember one thing

Secure your account first, set a budget alert, then build small. Everything else in AWS is a variation of these same few building blocks.
