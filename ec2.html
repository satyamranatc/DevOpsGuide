01

What EC2 is

A website, an app, or a script needs a computer to run on. That computer has to be switched on all day, have a steady internet connection, and be looked after.

EC2 (Elastic Compute Cloud) is how you rent one from AWS. You choose how powerful it is, press a button, and in about a minute you have a real server you can log into. It’s yours until you give it back.

AWS calls each rented server an instance. If you hear “spin up an instance”, it just means “start a server”.

In one line

EC2 is a computer you rent from AWS by the hour, with full control over what runs on it.

02

The hotel room idea

Renting an instance is a lot like booking a hotel room. These words map across neatly.

Instance

Your room. One rented server, ready to use.

AMI

How the room is furnished when you arrive. The starting software, such as Amazon Linux, Ubuntu or Windows.

Instance type

The room size. A cosy single or a big suite. It sets how much power and memory you get.

Key pair

Your room key. A secret file that proves you’re allowed in.

Security group

The front desk rules. Decides who may knock, and on which doors.

EBS volume

The wardrobe. The disk that stores your files and the operating system.

Public IP

The room’s street address, so people on the internet can reach it.

Region and zone

Which city, and which building, the hotel is in.

03

Choosing a size

Instance type names look cryptic, but they follow a simple pattern. Take t3.micro:

t

The family: what the server is good at. “t” is a cheap all-rounder for light work.

3

The generation. Higher is newer, usually a bit faster and better value.

micro

The size. From nano and micro up through small, medium, large, xlarge and beyond.

Each step up in size roughly doubles the power, and the price. A t3.micro has 2 virtual CPUs and 1 GB of memory, which is plenty for learning and small sites.

The families you’ll meet most

T and M

General purpose. Balanced CPU and memory. Start here for most apps.

C

Compute heavy. More CPU power, for things like video encoding.

R

Memory heavy. Lots of RAM, for big databases and caches.

G and P

Graphics cards. For machine learning and AI work.

A helpful habit

Start small. You can stop an instance and change its size later in a couple of minutes. It’s much cheaper than starting too big.

04

The whole picture

Here’s everything one instance is made of. You reach it through the security group’s doors, and prove who you are with your key.

05

Launch your first server

Let’s make one. Sign in to the AWS console, set a budget alert first if you haven’t, and check the region in the top-right corner. Then open EC2 and press Launch instance.

  1. Name it

    Type something you’ll recognise later, like my-first-server. This is just a label.

  2. Pick the software (AMI)

    Choose Amazon Linux. It’s free to use, made by AWS, and works well on EC2. The username you’ll log in with is ec2-user.

  3. Pick the size

    Choose t3.micro (or whichever is marked Free tier eligible in your region). It’s plenty for this guide.

  4. Create a key pair

    Press Create new key pair, name it my-key, keep RSA and .pem, and download it. You can’t download it again, so put it somewhere safe.

  5. Set the network rules

    Under network settings, allow SSH (so you can log in) and HTTP (so a website can be seen). For SSH, change the source from “Anywhere” to My IP, so only you can knock on that door.

  6. Check the disk, then launch

    The default 8 GB disk is fine. Press Launch instance. After a minute the state turns to Running.

06

Connect to it

Click your instance and copy its Public IPv4 address. Then open a terminal on your own computer, in the folder where you saved the key.

# the key must be private, or SSH will refuse it
chmod 400 my-key.pem

# log in (replace with your server's address)
ssh -i my-key.pem ec2-user@203.0.113.25

The first time, it asks whether you trust this server. Type yes. When the prompt changes to something like [ec2-user@ip-172-31-...]$, you’re inside your server.

Try a few commands, and type exit to leave.

# who am I, and where?
whoami
hostname

# how much disk and memory do I have?
df -h
free -h
Different software, different username

Amazon Linux uses ec2-user. Ubuntu uses ubuntu. Using the wrong one is the number one reason a login fails.

07

Put a website on it

A server isn’t much use until it does something. Let’s install a web server and show a page. While logged in, run these:

# install the nginx web server
sudo dnf install -y nginx

# start it now, and every time the server boots
sudo systemctl enable --now nginx

# write our own page
echo "<h1>Hello from my EC2 server!</h1>" | sudo tee /usr/share/nginx/html/index.html

Now open http:// followed by your public IP in a browser. You should see your message. You just hosted a website.

If the page doesn’t load, the cause is almost always the security group. Make sure HTTP (port 80) is allowed.

The shortcut: user data

Typing commands by hand doesn’t scale. When launching, open Advanced details and paste a script into User data. EC2 runs it automatically the first time the server starts, so it comes up already set up.

#!/bin/bash
dnf install -y nginx
systemctl enable --now nginx
echo "<h1>Hello from user data!</h1>" > /usr/share/nginx/html/index.html

An instance moves through a few states. The two that people mix up are stop and terminate, so here they are side by side.

09

Storage and addresses

Disks: EBS

An instance’s main disk is an EBS volume. It lives separately from the server, so a stopped instance keeps its files. You’re billed for the disk’s size the whole time it exists, even when the server is stopped.

You can add more volumes, and you can take a snapshot, which is a saved copy of a disk. Snapshots are your backups.

Addresses: why your IP keeps changing

Here’s a surprise many beginners hit. The public IP is not permanent. Stop and start the instance, and it gets a new one. Rebooting keeps it, but stopping doesn’t.

If you need an address that never changes, ask for an Elastic IP. It’s a fixed address you hold onto and attach to your server. You pay a small hourly fee for every public IPv4 address, so release it if you’re not using it.

Public IP

Free-ish and automatic, but changes when you stop and start.

Elastic IP

Stays the same until you let it go. Use it for something people rely on.

10

What it costs

You pay for an instance for the time it’s running. There are three main ways to pay, and they suit different jobs.

On-Demand

Pay by the second (for Linux) with no commitment. The default. Best for learning and unpredictable work.

Savings Plans

Promise to spend a set amount for one or three years, and get a big discount. Best for steady, always-on apps.

Spot

Use AWS’s spare capacity at a deep discount, but AWS can take it back with a two-minute warning. Best for jobs that can be interrupted.

Five habits that keep the bill small

  • Set a budget alert before you launch anything.
  • Stop or terminate servers you aren’t using. A forgotten instance bills all month.
  • Start small and only size up when you actually need to.
  • Release unused Elastic IPs and delete old volumes and snapshots.
  • Tag your servers with a name, so you can spot strays at a glance.

Free Tier offers change over time, so check the AWS Free Tier page for what applies to your account.

11

The same thing from the CLI

Everything above can be done with commands, which makes servers easy to create and delete in seconds. This assumes you’ve run aws configure (see the AWS essentials guide).

Create a key and a security group

# make a key pair and save the private half
aws ec2 create-key-pair --key-name my-key \
  --query KeyMaterial --output text > my-key.pem
chmod 400 my-key.pem

# make a security group
aws ec2 create-security-group --group-name web-sg \
  --description "Web and SSH"

# open web traffic to everyone, SSH only to you
# (use your own IP instead of 203.0.113.10)
aws ec2 authorize-security-group-ingress --group-name web-sg \
  --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-name web-sg \
  --protocol tcp --port 22 --cidr 203.0.113.10/32

Launch a server

# launch one t3.micro with the latest Amazon Linux
aws ec2 run-instances \
  --image-id resolve:ssm:/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 \
  --instance-type t3.micro \
  --key-name my-key \
  --security-groups web-sg \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=my-first-server}]'

Look after it

# list servers, their state and public IP
aws ec2 describe-instances \
  --query "Reservations[].Instances[].[InstanceId,State.Name,PublicIpAddress]" \
  --output table

# stop, start, and finally delete (use your own ID)
aws ec2 stop-instances      --instance-ids i-0123456789abcdef0
aws ec2 start-instances     --instance-ids i-0123456789abcdef0
aws ec2 terminate-instances --instance-ids i-0123456789abcdef0

These commands use your default network, which every new account has, so they work without any extra setup.

12

When things go wrong

SSH says “Permission denied (publickey)”

Wrong username or wrong key. Amazon Linux is ec2-user, Ubuntu is ubuntu. Check you’re using the key you launched with.

“Unprotected private key file”

The key file is readable by others. Run chmod 400 my-key.pem.

SSH just hangs and times out

The door is closed. Check the security group allows port 22 from your current IP. Home IPs change.

The website won’t load

Allow port 80 in the security group, and check nginx is running with sudo systemctl status nginx. Use http://, not https.

My IP address changed

You stopped and started the instance. Use an Elastic IP if you need a fixed address.

I lost my key file

It can’t be downloaded again. Launch a new instance with a new key, and copy your data across from a snapshot.

13

Quick recap

  • An instance is a server you rent from AWS by the hour.
  • The AMI is the software. The instance type is the power. t3.micro is a great start.
  • A key pair lets you log in. A security group decides which doors are open.
  • Log in with ssh -i key.pem ec2-user@ip.
  • Stop pauses a server. Terminate deletes it.
  • The public IP changes on stop and start. Use an Elastic IP to keep it.
  • Set a budget alert and delete what you’re not using.
If you remember one thing

An EC2 instance is just a computer you’re borrowing. Open only the doors you need, keep the key safe, and give it back when you’re done.
